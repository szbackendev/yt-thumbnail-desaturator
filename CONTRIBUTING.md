# Разработка и сопровождение

> **Language / Язык:** **Русский** | [English](CONTRIBUTING.en.md)

Пользовательское описание и установка: [README.md](README.md). Этот документ предназначен для разработки, тестирования и выпуска версий.

## Структура и архитектура

- `manifest.json` — WebExtension MV3, минимум Gecko `109.0`, ID `yt-thumb-desaturator@zen.browser`.
- `content/` — CSS-фильтры и ранняя инициализация при `document_start`; не добавляйте сканирование каждой карточки или поэлементные MutationObserver.
- `shared/settings.js` — нормализация, чтение `storage.sync` и `storage.local`, запись изменённых ключей в оба хранилища и live-события.
- `popup/`, `options/`, `donate/` — управление насыщенностью, язык и необязательная поддержка проекта.
- `tests/` — проверки ассетов, runtime, CSS/UI, документации и инструментов выпуска.
- `.github/workflows/` — CI для `dev`/`main`/PR и отдельная сборка по тегу релиза.

Фильтрация применяется к медиаэлементам превью, не к их предкам. Активное видео, аватары и баннеры должны оставаться цветными. Статичные и движущиеся превью проверяются отдельно.

При старте сохранённые ключи `storage.sync` имеют приоритет над локальным кэшем. После сбоя записи в sync следующий запуск может прочитать старое значение; долговременный протокол разрешения конфликтов не реализован. Значение по умолчанию применяется до асинхронного чтения настроек, поэтому переходный кадр не исключён.

## Рабочая ветка

Все изменения выполняются в `dev`. Прямые коммиты и push в `main` запрещены; продвижение производится через PR после проверок. Серверные ограничения зависят от настроек GitHub.

Команды выполняются из корня клона:

```powershell
git checkout dev
```

Сохраняйте `.gitattributes`: текст использует LF, PNG/XPI — бинарные файлы. Нормализация строк нужна для совпадения архивов из разных checkout.

## Тесты и сборка

Для сборки нужен Python 3.12+; полный набор тестов также требует Node.js 24+. Сторонние пакеты не требуются. Установленному расширению эти инструменты не нужны.

```powershell
python -m unittest discover tests -v
node --test tests/runtime.test.cjs
python package.py
```

Две дополнительные CSS/UI-проверки запускаются, если `THUMBNAIL_TEST_BROWSER` содержит абсолютный путь к уже установленному Chromium. Без переменной они явно пропускаются. Проверка локального `AGENTS.md` пропускается в чистом клоне: файл не входит в репозиторий. Chromium-фикстуры и модели API в Node.js не заменяют живую проверку Gecko/YouTube.

`python package.py --output <path>` создаёт отдельный архив; родительская папка должна существовать. Сборщик только упаковывает локальные файлы и проверяет ZIP; он не выполняет валидацию Mozilla и не подписывает дополнение. README RU/EN входят в XPI, поэтому после их изменения архив нужно пересобрать. Тестовые сборки используют временные файлы.

На Windows загруженный XPI может блокироваться браузером. Для разработки выбирайте `manifest.json`; перед заменой загруженного архива выгрузите дополнение либо закройте браузер. Не завершайте процессы браузера автоматически.

### Ручная проверка

1. `0%` / `100%`, ползунок, поле и пресеты.
2. Главная, поиск, рекомендации рядом с видео и динамическая подгрузка карточек.
3. Цветное активное видео и Shorts, аватары и баннеры.
4. Общее включение, обработка Shorts, восстановление цвета и движущиеся превью.
5. Сохранение после повторного открытия popup/обновления страницы и live-изменения в двух вкладках.
6. RU / EN / Auto.

Отмечайте версию браузера и границы проверки; успешная проверка одного профиля не подтверждает все версии Gecko и варианты разметки YouTube.

## Подготовка релиза

Новая версия должна быть выше текущей. Gecko ID не меняется.

```powershell
python bump_version.py patch
```

Команда работает только в `dev`, запускает тесты и пересобирает XPI. При сбое восстанавливаются прежние байты манифеста и архива; неизменившийся файл не перезаписывается. Ошибка восстановления явно обозначается как неполный откат.

Перед коммитом проверьте diff, добавьте конкретные изменённые файлы и пересобранный XPI, затем отправьте `origin dev`. Создайте PR в `main`, дождитесь CI и выполните ручную проверку. Чистый клон должен проходить тесты и собирать архив, соответствующий исходникам.

GitHub Release запускается отдельно отправкой тега `v<version>`, совпадающего с манифестом и указывающего на коммит в `main`.
